#+title: Paper video-text retrieval preflight

* Contract

This bounded readiness check tests one architecture in two implementations:
=LCO-Embedding/LCO-Embedding-Omni-3B-2605= at revision
=5f6b5329da5141367da30e06a9826d1322d6c9b2= in Representax and Sentence
Transformers 5.6.1. Both ran sequentially on physical GPU 0, an RTX 4090.

The deterministic data view contains eight training videos and eight video
queries with 32 caption documents. Every video has exactly 16 decoded 224px
frames. Training data is pinned to =VLM2Vec/MSR-VTT= revision
=947b139d0c591235a3f311e45a31a88461bad0d2=; evaluation is pinned to
=mteb/MSR-VTT= revision =4661603cee25c1fd370e5478a2953203cf37155b=.
Both implementations use seed 7, batch 2, four updates, BF16 compute, text LoRA
rank 4, cached MNR with microbatch 1, and the checkpoint's default system
prompt. This is a small preflight, not a paper result.

| Warm examples/s | 2.8605 | 1.4569 |

Representax reached =1.9634x= the warmed reference throughput. Initial
cross-framework embedding parity on the complete held-out slice had mean
cosine 0.99909 for video queries and 0.99985 for caption documents; all eight
top-1 retrieval results were identical.

* Findings

- Multimodal processor output had flattened vision tensors across sample rows.
  Vision tensors and insertion indices are now row-major, and direct versus
  GradCache updates are covered for a two-video batch.
- The native processor concatenated Sentence Transformers' default prompt into
  the user text. The checkpoint contract requires a structured system message;
  the corrected token IDs now match the reference.
- The reference trainer does not implicitly apply its model's default prompt,
  so the runner passes that prompt explicitly for both training columns.
- Storing frame arrays inside an Arrow Dataset caused recursive scalar
  conversion and multi-minute trainer startup. The runner stores paths and
  loads the already-decoded arrays in a batch transform. Automatic model-card
  statistics are disabled because they would rescan every frame.

Both implementations completed initial/final evaluation, four finite updates,
midpoint checkpoint/resume, final checkpoint, export, and inference reload.
There are no dataset access or decoding blockers. The small sample and two
warmed Representax steps are sufficient for readiness only; the paper run must
use the frozen full workload.

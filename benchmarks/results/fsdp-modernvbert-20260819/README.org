#+title: Single-host DDP/FSDP ModernVBERT profile — 2026-08-19

* Decision

Representax expresses named DDP and full-model FSDP as one global JAX program
with different input/output shardings. DDP keeps model and Adam state replicated
and shards the example axis. FSDP keeps model and Adam state sharded at rest,
logically replicates parameters at the complete-model compute boundary, and lets
JAX transpose that program back into sharded gradients. Neither preset owns a
separate trainer or hand-written gradient synchronization path.

An optional =materialization_boundary="layer"= mode remains for workloads that
need a shorter gathered-parameter live range. That is a distinct capacity
optimization: it uses an explicit model capability naming the scanned layer
stack and rejects unsupported architectures. Full-model FSDP is the generic,
annotation-driven default.

* Correction to the first profile

The first version of this document accepted the manual DDP and model-FSDP
programs because their one-step comparisons were close and their systems
profiles looked favorable. A ten-update trajectory audit disproved that
acceptance: their final loss was approximately =0.34= while a clean one-device
execution of the same scientific program reached approximately =1.18=. Those
timings therefore measured a different optimizer trajectory and are not valid
DDP/FSDP performance baselines.

The current benchmark discards warmup output, records every measured update,
and fingerprints every model and optimizer leaf. The global-program form is
accepted only against that complete evidence. Superseded artifacts remain under
=/raid= for diagnosis provenance; no result below uses them.

* Workload and evidentiary boundary

The corrected matched workload uses the real 149M-parameter
=ModernVBERT/modernvbert-embed= checkpoint, four physical RTX 4090s (GPUs 2--5),
global batch 16, sequence length 128, exact GradCache chunks of 2, FP32/highest
matmul precision, AdamW, one discarded warmup, and ten synchronized measured
optimizer updates. Inputs are deterministic random token IDs with an identity
query/document positive relation.

This is a complete forward/backward/optimizer systems program. Model-ready
synthetic tensors deliberately remove storage, tokenization, and semantic data
quality as confounders. It tests numerical trajectory, placement, memory, and
sustained-step behavior; it is not retrieval-quality evidence.

row is the reference scientific trajectory, not a scaling baseline: all rows
retain the same small global batch of 16.

The annotation-driven DDP program is 0.5% slower than the one-device reference
at this deliberately fixed, small global batch and is 26% faster than the
superseded manual 0.4745-second path. Full-model FSDP quarters persistent model
and Adam bytes and lowers peak live JAX memory by 38% relative to DDP, but is
4.58x slower on this PCIe-only topology because its gathered full model remains
live through each GradCache encoder replay. It is presently a valid capacity
mode, not a throughput win.

The first update agrees to approximately =1e-6= absolute loss. Floating-point
reduction-order differences then accumulate during this deliberately rapid
overfit, reaching =0.0410= absolute loss for DDP and =0.0625= for FSDP at update
ten. The final model squared-sum signature remains within =1.59e-6= relative
error and the largest absolute parameter within =3.23e-5= relative error. Strict
ten-update array parity is separately enforced on deterministic tiny
ModernVBERT programs; the full-checkpoint trace records realistic topology
drift rather than imposing a misleading relative-loss threshold near zero.

Nsight Systems traces of one warmup plus three measured steps confirm physical
compiler-generated communication on all four GPUs. Across the complete trace,
DDP launches 768 NCCL AllGather, 896 FP32 AllReduce, and 256 SendRecv kernels;
the AllGathers exchange global GradCache representations. Full-model FSDP
launches 160 NCCL AllGather, 32 FP32 ReduceScatter, and 3,068 FP32 AllReduce
kernels. The latter communication schedule is valid but plainly not yet
optimal, and it is now a measured target for the physical frontier work rather
than hidden behind hand-authored collectives.

The post-partition compiled HLO independently contains 6 AllGather, 7 AllReduce,
and 2 AllToAll instructions for DDP; full-model FSDP contains 8 AllGather, 9
AllReduce, and 1 ReduceScatter instruction. Pre-partition StableHLO correctly
contains none of these compiler-inserted operations, which is why the benchmark
now records both stages rather than searching only the initial lowering.

* Why full-model FSDP is annotatable

The at-rest =PartitionSpec= tree is part of =ShardingPlan=. The compiled step
accepts and returns that sharded model and the matching sharded Optax state.
Immediately around the model call, Representax annotates each parameter as
replicated. JAX inserts the communication required to reconcile those layouts;
reverse-mode transposes the replicated read into a sharded parameter gradient.
The task, optimizer, and training-loop control flow remain unchanged.

Layer-boundary FSDP asks for a stronger property: do not keep the complete
materialized model live. The compiler cannot infer the semantic layer boundary
from an arbitrary Equinox PyTree, so models opting into that mode identify their
layer stack via =fsdp_materialize()=. This does not limit the generic full-model
mode.

* Automated acceptance

The distributed suite exercises DDP, same-axis FSDP, parameter-only FSDP, 2x2
hybrid data/model sharding, custom partition rules, and Orbax sharded restore on
two- and four-device virtual topologies. ModernVBERT additionally runs ten
optimizer updates for both full-model and layer-boundary FSDP on two- and
four-device meshes, comparing every array leaf with the one-device state after
each matched scientific program.

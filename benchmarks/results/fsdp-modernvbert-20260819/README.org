#+title: Single-host DDP/FSDP ModernVBERT profile — 2026-08-19

* Decision

Representax expresses named DDP and full-model FSDP as one global JAX program
with different input/output shardings. DDP keeps model and Adam state replicated
and shards the example axis. FSDP keeps model and Adam state sharded at rest,
coalesces compatible parameter leaves into sharded global buckets, annotates the
packed compute boundary as replicated, and lets JAX transpose that program back
into sharded gradient buckets. Neither preset owns a separate trainer or a
hand-written full-model collective path.

An optional =materialization_boundary="layer"= mode remains for workloads that
need a shorter gathered-parameter live range. That is a distinct capacity
optimization: it uses an explicit model capability naming the scanned layer
stack and rejects unsupported architectures. Full-model FSDP is the generic,
annotation-driven default.

* Correction to the first profile

The first benchmark retained its warmup update before timing ten more updates.
Its final loss of approximately =0.34= therefore describes eleven optimizer
updates, whereas the corrected profiles below discard warmup state and describe
ten. A corrected rerun established that the historical explicit-collective FSDP
program was valid: it sustained 31.624 examples/s and reached a final loss of
=0.530222=. It is retained as a control, not as the production implementation.

The current benchmark discards warmup output, records every measured update,
and fingerprints every model and optimizer leaf. The global-program form is
accepted only against that complete evidence. Superseded artifacts remain under
=/raid= for diagnosis provenance; no result below uses them.

* Workload and evidentiary boundary

The corrected matched workload uses the real 149M-parameter
=ModernVBERT/modernvbert-embed= checkpoint, four physical RTX 4090s (GPUs 2--5),
global batch 16, sequence length 128, exact GradCache chunks of 2, FP32/highest
matmul precision, AdamW, one discarded warmup, and ten synchronized measured
optimizer updates. Inputs are deterministic random token IDs with an identity
query/document positive relation.

This is a complete forward/backward/optimizer systems program. Model-ready
synthetic tensors deliberately remove storage, tokenization, and semantic data
quality as confounders. It tests numerical trajectory, placement, memory, and
sustained-step behavior; it is not retrieval-quality evidence.

contained 8/9/1 and diagnosed the fragmented materialization boundary. A fresh
Nsight trace for the accepted program remains part of the larger capacity and
topology frontier rather than a condition for this program-level acceptance.

* Gradient and axis-type annotation experiment

A follow-up experiment asked where to put the annotation that recovers the
explicit-collective control's compact schedule:

| global-program variant | examples / second | compiled AG / AR / RS |
|------------------------+-------------------+-----------------------|
| Auto, bucketed global boundary | 31.68 | 2 / 6 / 2 |
| Explicit, bucketed global boundary | 31.61 | 2 / 6 / 2 |
| plan-driven explicit-collective control | 31.62 | 2 / 6 / 2 |
| Auto, unbucketed full-model boundary | 10.09 | 8 / 9 / 1 |
| Auto, post-backward sharded-gradient constraint | 9.56 | 8 / 10 / 1 |
| Explicit, post-backward sharded-gradient constraint | 9.50 | 8 / 10 / 1 |
| Auto, parameter use-site materialization | 6.00 | 19 / 4 / 7 |

The post-backward constraint is too late: autodiff has already selected the
transpose of the replicated model boundary, so it only adds synchronization.
Instead, the accepted program reshapes and concatenates compatible global
parameter leaves while retaining their sharded annotation, annotates the packed
bucket as replicated, then slices it for the ordinary model forward. Autodiff
transposes that identity into the matching sharded gradient bucket. No custom
VJP or full-model explicit collective is required.

=AxisType.Explicit= remains valuable as a validation lane because illegal
sharding propagation becomes a trace-time error. It reaches the same collective
schedule and steady-state rate, but compiled in 18.55 seconds versus 0.89 for
=Auto=. =Auto= therefore remains the measured runtime default.

* Why full-model FSDP is annotatable

The at-rest =PartitionSpec= tree is part of =ShardingPlan=. The compiled step
accepts and returns that sharded model and the matching sharded Optax state.
Immediately around the model call, Representax coalesces leaves by dtype and
mesh axis, annotates each packed bucket first in its at-rest layout and then as
replicated, and reconstructs the ordinary model PyTree. JAX inserts the
communication required to reconcile those layouts; reverse-mode transposes the
replicated read into a matching sharded gradient bucket. The task, optimizer,
and training-loop control flow remain unchanged.

Layer-boundary FSDP asks for a stronger property: do not keep the complete
materialized model live. The compiler cannot infer the semantic layer boundary
from an arbitrary Equinox PyTree, so models opting into that mode identify their
layer stack via =fsdp_materialize()=. This does not limit the generic full-model
mode.

* Automated acceptance

The distributed suite exercises DDP, same-axis FSDP, parameter-only FSDP, 2x2
hybrid data/model sharding, custom partition rules, and Orbax sharded restore on
two- and four-device virtual topologies. ModernVBERT additionally runs ten
optimizer updates for both full-model and layer-boundary FSDP on two- and
four-device meshes, comparing every array leaf with the one-device state after
each matched scientific program.

* DONE Implement exact native-JAX GradCache as an execution plan for MNR :retrieval:runtime:
  Preserve =MNRTask= and one shared row-level MNR primitive as the sole
  scientific definition.
  GradCache changes only the differentiation schedule: encode fixed-shape chunks
  while retaining the full logical negative population, differentiate the same
  MNR loss with respect to the representations, replay one encoder chunk at a
  time with its cached cotangent, and perform one ordinary optimizer update.

  Start with a small native-JAX transform: =lax.scan= a
  =jax.checkpoint(..., policy=nothing_saveable)= encoder body and let JAX's
  transpose synthesize the reverse replay. Keep query and document chunk sizes
  in =ExecutionPlan=, pad only the execution batch with validity masks, and
  derive explicit per-role and per-chunk PRNG keys so stochastic forwards replay
  exactly. Do not add a cached task, a second MNR formula, Python backward hooks,
  or a second optimizer path.

  Treat Pallas as a later representation-kernel optimization, not as the
  GradCache orchestrator: an encoder replay must remain ordinary Equinox/JAX.
  Profile the representation-loss stage first, then consider a tiled Pallas
  custom VJP for normalized similarity, log-sum-exp, and embedding cotangents
  only if it is numerically equivalent and beats XLA. Keep a native-JAX tiled
  fallback for unsupported accelerators.

  Correctness gates compare direct and cached loss, representation cotangents,
  parameter gradients, clipping, optimizer state, and updated parameters across
  asymmetric and symmetric MNR, graded positives, Matryoshka dimensions,
  padding, partial chunks, tied routes, and stochastic dropout. A systems gate
  must show that peak activation memory follows encoder chunk size rather than
  logical batch size.

  Use Sentence Transformers' current =CachedMultipleNegativesRankingLoss= as a
  pinned cross-framework reference and target to beat on the same ModernVBERT
  weights, inputs, pooling, scale, precision, optimizer, and logical negative
  population. Report compilation separately from warmup and steady-state time;
  report OOM boundaries, throughput, and allocator/process peak memory. Relative
  performance produces an explicit warning rather than a flaky correctness
  failure, but this item is complete only when Representax fits every matched
  batch the reference fits and is faster and tighter at steady state. Extend the
  same semantics to global negatives across devices and hosts only afterward.

** DONE Close the remaining allocator and compilation gaps against the pinned reference :performance:
   The canonical transaction is now one ordinary Equinox/Optax update followed
   by =optax.tree.where= over a named proposed =TrainState=.  The controlled
   final sequence-512, chunk-two matrix in
   =benchmarks/results/grad-cache-final-20260813/= matches loss to =4.77e-7=
   absolute and gradient norm to =7.64e-5= relative through batch 1,024.
   Representax fits every declared reference point, is 16.1% to 26.7% faster,
   and uses 1.27% to 1.36% less process-visible device memory.  Its allocator
   peak stays within 1.03% of the reference and grows only 14.6 MiB across the
   matrix.  A second fresh process using the populated persistent compilation
   cache reduces compile plus first execution from 39.086 to 3.621 seconds,
   beating the reference's 4.352-second first step.  Keep state donation
   explicit at the generic callable boundary; the linear loop may combine it
   with Orbax V1 async saves after their blocking device-to-host snapshot
   returns.
** DONE Validate exact GradCache across single-host device and process topologies :distributed:
*** DONE Verify exact replicated data parallel GradCache on two and four GPUs
    Keep model and optimizer placement separate from GradCache semantics through
    a named =DataParallel= sharding plan.  Shard query and document records over
    the =data= mesh axis, gather only compact representations and relation
    metadata for the global negative pool, replay encoder chunks locally, and
    synchronize replicated parameter gradients once before the Optax update.

    Acceptance requires the same ModernVBERT checkpoint, global batch, MNR
    relation, precision, and optimizer update to agree on one, two, and four
    GPUs.  Compare loss, task metrics, gradient norm, optimizer state, and
    updated parameters; include a canary whose decisive negative lives on a
    different device.  Record compile time, steady-state step time, and peak
    memory separately for each topology on GPUs 0, 1, 2, and 3.

    Accepted on 2026-08-14 with JAX 0.10.1 and four RTX 4090s.  The pinned
    ModernVBERT checkpoint used global batch 16, sequence length 512, chunk
    size 2, FP32 highest precision, and one AdamW update.  Both world sizes
    match the one-device cached update to =4.77e-7= loss absolute, exactly match
    the reported gradient norm, remain within =1.09e-6= maximum parameter
    absolute, and keep optimizer-state relative L2 at about =1.02e-6=.  A
    symmetric Matryoshka test separately proves the complete optimizer update
    and a cross-device hard-negative canary on both topologies.  See
    =benchmarks/results/distributed-grad-cache-modernvbert-20260814/=.
*** DONE Accept process-local data and global negatives across JAX processes
    Construct globally sharded batches with
    =jax.make_array_from_process_local_data= so each process supplies only its
    local query/document records and validity vectors.  A process-local
    retrieval relation owns local query rows against the complete global
    document axis, preserving arbitrary cross-process positives as well as
    negatives without replicating token payloads.

    Acceptance uses two JAX processes with two GPUs each on GPUs 0, 1, 2, and
    3.  The same ModernVBERT checkpoint, global batch, sequence length,
    precision, MNR relation, and optimizer update must match a one-process
    global oracle on both processes.  This validates the process boundary and
    collective semantics on available hardware, but is not evidence about a
    physical inter-host network.

    Accepted on 2026-08-14 with two JAX processes, two RTX 4090s per process,
    and one physical host.  The process-local ModernVBERT batch includes a query
    whose sole positive document belongs to the other process.  Both workers
    produce the same distributed result.  Against their one-device global
    oracle, loss differs by =2.38e-7= absolute, gradient norm by =1.07e-5=
    relative, updated parameters by =1.77e-6= relative L2, and Adam state by
    =9.43e-4= relative L2 at =0.99999956= cosine.  Median steady-state time is
    =0.630= seconds for global batch 16 at sequence length 512.  See
    =benchmarks/results/multiprocess-grad-cache-modernvbert-20260814/=.

* DONE Support activation rematerialization as a measured execution choice :runtime:memory:
  Expose =none=, =selective=, and =full= as topology-dependent policies without
  changing model parameters or scientific semantics.  =selective= uses JAX's
  transformer-oriented =dots_with_no_batch_dims_saveable= policy; do not expose
  unstable custom policy callables as public configuration.

  Complete this slice only when all policies preserve forward and gradient
  parity, the pinned Transformers oracle still passes, and isolated sequence-512
  ModernVBERT runs report compile-plus-first time, steady-state throughput,
  allocator peak, and process peak.  Choose the default from measured evidence,
  document the tradeoff, and keep any performance shortfall as a warning rather
  than a numerical failure.

  =full= remains the measured default.  At direct batch 8 and sequence 512,
  =selective= is 5.9% faster but raises allocator peak from 4.259 to 8.129 GiB
  and process peak from 8.402 to 16.402 GiB; it OOMs at batch 32, where =full=
  completes at 7.590 GiB allocator peak.  =none= completes batch 4 at 14.757 GiB
  and OOMs at batch 8.  Native value/parameter-gradient equivalence, all-policy
  pinned Transformers forward/input-gradient parity, 53 fast tests, and 9
  runtime tests pass.  Evidence lives in
  =benchmarks/results/modernvbert-rematerialization-20260813/=.

# Hugging Face interoperability

Representax treats Hugging Face checkpoints as an interchange format, not as
its model runtime. Native Equinox modules remain the trainable source of truth.
PyTorch and upstream Transformers implementations are confined to optional
parity tooling.

## Versioned architecture catalog

The v0 catalog freezes every configuration model type and task-neutral
`AutoModel` mapping exposed by Transformers 5.3.0. The generated catalog is
Torch-free and lets configuration dispatch fail deterministically instead of
changing when an ambient Transformers installation changes.

Catalog coverage is not a native-support claim. Each definition has an explicit
support state:

- `catalogued`: the upstream architecture identity is known;
- `native`: a native Equinox definition exists but has not completed acceptance;
- `verified`: the native definition passes the required numerical and systems
  gates.

ModernVBERT is the first `verified` architecture. New model types are added by
updating the pinned Transformers reference and regenerating the catalog; native
forwards are implemented once per reusable architecture family.

The separate semantic family manifest is reviewed Python data. Each entry owns
one or more pinned model types and names its modalities, reusable numerical
components, configuration adapter, accepted input and output contracts,
checkpoint layout, implementation module, and completed acceptance gates. The
generator rejects stale catalogue fingerprints, unknown or multiply owned model
types, and unearned support claims, then emits the immutable Torch-free runtime
index. It does not inspect or translate upstream forward source.

This makes generation useful without pretending architecture ports are
mechanical: codegen owns dispatch and acceptance scaffolding, while humans own
the semantic decomposition and native Equinox implementation.

Each model family owns one bidirectional checkpoint adapter with three explicit
parts:

1. a mapping from the upstream configuration into the native architecture;
2. a declarative mapping between native parameter paths and upstream tensor
   names; and
3. small, pure tensor transforms for layouts that require splitting, stacking,
   reshaping, transposition, padding, or scaling.

The shared integration layer only reads configuration files and selected
safetensor shards. It does not know model-specific names. Tokenizers,
processors, model cards, and custom code remain checkpoint assets and will be
copied or regenerated by a later complete export workflow.

This design borrows two useful ideas from existing JAX projects:

- [Levanter's checkpoint converter](https://github.com/marin-community/levanter/blob/main/src/levanter/compat/hf_checkpoints.py)
  makes configuration, import, export, tokenizer, and feature-extractor behavior
  a bidirectional model-family boundary.
- [MaxText's conversion utilities](https://github.com/AI-Hypercomputer/maxtext/tree/main/src/maxtext/checkpoint_conversion)
  keep parameter-name maps separate from transformation hooks.

Representax implements its own smaller Equinox-oriented boundary. No MaxText or
Levanter source is vendored.

## Support contract

A checkpoint integration is not considered supported merely because its
weights load. It must demonstrate:

- configuration and tensor-name coverage;
- state-dict import and export round trips;
- upstream forward and input-gradient parity;
- parameter-gradient and optimizer-update parity before training claims; and
- export followed by upstream reload before publishing trained artifacts.

Large upstream fixtures stay outside Git. Ordinary CI uses tiny native models
and mapping tests; scheduled parity jobs generate or consume pinned upstream
oracles through the optional parity environment.

ModernVBERT's complete adapter maps its text tower, SigLIP patch and position
embeddings, twelve vision blocks, post-normalization, and modality connector.
It intentionally omits the upstream SigLIP pooling head: Transformers computes
that value and replaces it with connector patch features before the
ModernVBERT forward consumes it. Representax maps every executed tensor rather
than carrying dead parameters and computation.
